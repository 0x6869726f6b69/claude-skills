# Storyboard: 分析結果を Figure にまとめる

## 1. 所見カード — 結果を「何を示すか」に翻訳する

棚卸しした結果ごとに1行のカードを作る。ファイル名ではなく「何が言えるか」で考えるのが出発点。

| 項目 | 例 |
|---|---|
| ID・ソース | #6 results/benchmark.csv（#1 accuracy_bar.pdf と同じデータ） |
| 所見（1文、平叙文） | 提案手法は3データセットすべてで最高精度（平均 +6.1 pt vs SOTA-X） |
| 主張の型 | overview / mechanism / performance / generalization / limitation / application |
| 証拠の強さ | n = 5 seeds、SD 0.4–1.2 pt、効果量大 |
| 新規性 | 既知の確認か、新しい現象か |
| 再描画可否 | データあり（csv）／画像のみ／データ不明 |

## 2. 主張とストーリー

1. 論文全体の主張（thesis）を1文で書く。
2. thesis を支える主張を 3–6 個に分解する。**1つの主張 = 1つの Figure**。
   主張はトピック（"Benchmark results"）ではなく結果の文（"X reduces error 3-fold across all
   benchmarks"）で書く。これがそのまま Caption のタイトル文になる。
3. 主張をストーリー上の役割に割り当てる。

| 流れ | Figure の役割 | 典型的なパネル |
|---|---|---|
| **What**（課題と着想） | Fig. 1 概要 | 課題の模式図、従来 vs 提案の対比、出力例、主要成果1つ |
| **How**（仕組み） | 手法・プロトコル | 構成の詳細、中間表現の可視化、制御された条件での検証 |
| **Why**（なぜ効くか） | 機構・解析 | アブレーション、寄与分析、物理/生物学的な解釈 |
| **Performance** | 先行研究との比較 | 複数データセットでの比較、精度–コストのトレードオフ、スケーリング |
| **Impact** | 応用・新発見 | 手法で初めて可能になった発見、実データでの事例、汎化と限界 |

手法論文でなく発見型の論文なら: 研究デザイン/データ概要 → 主要な発見 → 機構 → 検証・再現 → 意義。
Figure の数は Nature の Article で本文 4–6 枚程度が目安（投稿先の上限を確認）。

## 3. まとめ方のルール

- 結果は「最も直接に支える主張」の Figure に入れる。どの主張も支えないものは SI か不採用。
- 1 Figure は 3–8 パネル（典型 4–6）。2 パネル以下なら隣の Figure に統合、9 以上なら分割するか
  重要度の低いものを SI へ。
- Figure 内の順序: 設定・定義 → 主要な証拠（hero）→ 頑健性・内訳 → 具体例・含意。
- 数値の改善には必ず具体例を組み合わせる（誤差指標＋再構成例、精度＋判定が変わった実例）。
- 多数データセットでの同じ比較は、本文では1パネルに集約（ドットプロットや heatmap）し、
  データセット別の詳細曲線は SI へ。
- ハイパーパラメータ掃引、実装の健全性チェック、冗長な指標は SI へ。
- 限界・失敗例を少なくとも1つ正直に示す（本文の後半 Figure のパネル、または SI で本文から参照）。
- 同じデータを本文の2つの Figure に重複して載せない。Fig. 1 の「主要成果」パネルと後の性能比較
  Figure が同じベンチマークになりそうなときは、Fig. 1 側を別の切り口（代表例の誤差マップ、1条件の要約、
  応用上の数字）にし、網羅的な比較は後の Figure に任せる。
- README・原稿・ユーザーが述べている主張（「CFD より100倍速い」等）には、それを裏付けるパネルか表を
  必ず用意する。裏付けるデータがなければ図で補わず、`[AUTHOR TODO]` として報告する。
- 既存の図の形式が主張に合っていなければ作り直す（例: 点のない棒グラフ → 点＋平均±SD）。

## 4. Figure 1（概要図）の型

Figure 1 は論文を読まなくても「何が問題で、何を提案し、何が得られ、どれだけ良いか」が分かること。

```
2カラム 183 × 110–140 mm
nfig.figure("double", 120, rows=[("a", 0.9), ("bcd", 1.1)])   # 行ごとに独立したレイアウト
 a: 概念の流れ（研究課題 → 提案手法 → 出力）。全幅、高さ 35–50 mm
    従来法と提案法を2段（nfig.pipeline を2回）で並べ、新しい部分だけアクセント色
 b: 提案手法の核心（仕組みの模式図 or 中間表現の実例）
 c: 代表的な出力例（実データ。模式図だけで終わらせない）
 d: 主要成果を1つ（提案 vs 最強の比較手法、ばらつき付き）
```

- 模式図の箱は短い言葉で。装飾アイコンは使わず、現実の文脈を補うものだけ使う。
- アクセント色は「新しいもの」にだけ使い、その色を以降の Figure でも提案手法の色として使う。
- 少なくとも1パネルは実データにする。
- 外部ツール（Illustrator, PowerPoint, BioRender 等）で描いた概要図がある場合は、PDF のまま
  `assemble.py` で組み込み、文字サイズ報告で 5–7 pt に収まるようにセルの大きさを決める。

## 5. レイアウト型と寸法

`nfig.figure(width, height_mm, mosaic=...)` に渡す mosaic。小文字1字のキーがパネルラベルになる
（"." は空き、"c2" のような複数文字キーはラベルなしの補助 axes）。

| 型 | mosaic | 使いどころ |
|---|---|---|
| Banner + row | `rows=[("a", 0.9), ("bcd", 1.1)]` | 概要図（Fig. 1）、上段に模式図、下段に証拠 |
| Banner + map strip + plot | `rows=[("a", .8), ("bcdef", 1), ("g", 1)]` | 模式図／場のマップ列（共通カラーバー）／断面などのグラフ |
| Hero-left | `"aab;aac"` | 決定的な結果1つ＋補助2つ |
| Hero-top | `"aa;bc"`, `"aaa;bcd"` | hero が横長（時系列、多条件の比較） |
| Small multiples | `"abc;def"` | 同じ種類のグラフを条件違いで（sharey、凡例1つ） |
| Hero + example strip | `"aab;aac;ddd"` | 定量（a–c）＋具体例の画像列（d） |
| Comparison grid | `"ab;cd"` | 2×2（条件 × 指標） |
| 1カラム | `"a;b"`, `"ab;cc"`, `"a;b;c"` | 89 mm 幅、1行あたり 45–60 mm |

**行ごとにパネルの種類が違うとき（模式図・画像/マップ・グラフが混在）は必ず `rows=` を使う。**
1つの mosaic では、constrained layout が列ごとに余白を揃えるため、下段グラフの目盛りラベルの余白が
上段の画像列にも入り、画像やマップが数 mm に潰れる（QA は "squeezed" と警告する）。
逆に、同種の行だけ（グラフだけ、マップだけ）なら1つの mosaic のほうが列の端が揃うので `rows=` は使わない。
さらに複雑な入れ子（右半分だけ 3×3 の画像グリッド等）は `fig.subfigures()` を直接使う。
`label_panels` には全パネルの axes を dict で渡す（subfigure をまたいでも整列する）。

寸法の目安（2カラム 183 mm）:
- 標準的なグラフの行: 高さ 40–55 mm（1行に 3–4 パネル）。データ領域の幅は 25 mm 以上。
- hero は support の 1.5–2 倍の面積。
- 全幅の模式図バナー: 35–50 mm。画像列: 画像の縦横比から決める。
- 合計 170 mm 以下。足りなければパネルを SI へ移す（文字を小さくして詰め込まない）。
- `width_ratios` / `height_ratios` で比率を調整し、QA で余白・詰まりを確認して反復する。

## 6. おまかせ時の設計手順

ユーザーが「おまかせ」または具体的な指示なしの場合、次の手順で Claude が決める。

1. **棚卸し**: inventory.py とコンタクトシートで全結果を見て、所見カードを作る（§1）。
2. **主張**: thesis と 3–6 個の主張を書き、ストーリー上の役割を割り当てる（§2）。
   結果が1枚分しかなければ、hero＋support からなる強い1枚を作る。
3. **採否の採点**: 各所見を 0–2 点 × 4 項目で採点する —
   主張との関連 / 効果の明瞭さ / 新規性 / 頑健性（ばらつき・n）。
   合計 5 点以上は本文候補、それ未満は SI。例外: 限界・失敗例は点数に関わらず最低1つ残す。
   README・原稿で述べている主張の証拠も点数に関わらず本文に残す（§3）。
4. **割り当て**: 本文候補を Figure に振り分け、1 Figure 3–8 パネルに収める。各 Figure の hero を決める
   （主張を最も直接に証明するパネル）。
5. **型と寸法**: §5 から型を選ぶ。多パネル図は 2カラム、2–3 パネルの小さな図は 1カラム。
6. **グラフ形式**: charts.md の「主張の型 → グラフ」で選び直す（元の形式に縛られない）。
7. **配色の役割**: 全 Figure 共通で proposed / highlight / baseline / reference を決め、
   figure_style.json に保存。
8. **計画書**: figure_plan.md を書き、作図・QA へ。報告時に「こう判断した理由」と
   「さらに強くするには何が足りないか」（欠けている対照実験、誤差棒のない結果など）を添える。

## 7. よくある失敗

- 実験した順に1実験1図を並べる（実験ノート型）→ 主張ごとに再構成する。
- 役割の分からないパネル、同じことを言う重複パネル。
- Figure ごとに同じ手法の色が変わる。凡例を全パネルで繰り返す。
- グラフ内のタイトルが Caption と重複している。
- 虹色カラーマップ、3D棒、影、背景グリッド。
- スクリーンショットや既存PNGの貼り合わせでフォント・線幅がばらばら。
- 縮小前提で描き、最終サイズで文字が 5 pt を下回る。
