## A. Nature系の学術雑誌に採択されることを意識したFigure・Tableの作成指針

### 1. 科学的ストーリー・新規性
- 1 Figure = 1つの明確な科学的主張とし、複数パネルでその主張を多面的に裏付ける。
- Figure 1 は研究全体の概要図とし、「研究課題 → 提案手法 → 出力 → 主要な成果」を1枚で理解できる構成にする。
- 従来手法との差異を視覚的に明示し、何が新しく、なぜ重要なのかを直感的に伝える。
- 単なる性能向上だけでなく、従来の知見では説明できなかった現象・新しい発見・科学的インパクトを強調する。
- Figure 間に論理的なつながりを持たせ、What → How → Why → Performance → Impact というストーリーを構築する。
- 実験結果の羅列を避け、Figure 自体が論文の主張を裏付ける証拠となるように設計する。

### 2. 情報量・パネル構成
- 複数パネル（a, b, c, …）を組み合わせ、概念図・定量比較・可視化・具体例を統合する。
- 情報密度を高める一方、可読性を犠牲にしない。単位面積あたりの有用な情報量を最大化する。
- 最重要のパネルを大きく配置し、補助的なパネルを小さくすることで、視覚的な優先順位を明確にする。
- パネルの配置は読み順を考慮し、左上から右下へ自然に論理が展開する構成にする。
- 意味のない余白は削減しつつ、パネル間や図形間には十分な余白を確保する。
- 同種のグラフはサイズ・軸・余白・ラベル位置を統一し、厳密に整列させる。
- 本文 Figure には主要な結果を優先して掲載し、細かな条件比較や追加実験は Supplementary Information に配置する。

### 3. 配色・デザイン
- 使用色は原則3〜5色程度に抑え、色ごとに明確な意味を持たせる。
- 提案手法・比較手法・基準値などの色の対応を、すべての Figure で統一する。
- 灰色を積極的に活用し、比較対象や補助情報を目立たせず、重要な結果を有彩色で強調する。
- 彩度を抑えた青・橙・赤などを使用し、過度に派手な原色や装飾を避ける。
- 背景は原則白とし、不要なグリッド・影・立体効果・装飾的な枠線を排除する。
- 色だけに依存せず、線種・マーカー形状・濃淡でも情報を区別できるようにする。
- Figure 全体で統一されたデザイン言語を採用し、論文としての一貫性を確保する。

### 4. グラフ・定量評価
- 提案手法と先行研究の比較を同一グラフ内に配置し、優位性や差異を直接確認できるようにする。
- 平均値だけでなく、標準偏差・信頼区間・分布・個別データなどを示し、結果の頑健性を伝える。
- Scatter plot・line plot・box plot・heatmap など、科学的主張に最適なグラフ形式を選択する。
- 軸の範囲・スケール・単位を適切に設定し、性能差を誇張しない。
- 必要に応じて対数軸を使用し、計算時間・メモリ・誤差などの桁違いの差を明確に示す。
- 定量結果と具体的な実例を組み合わせ、数値上の改善が実際に何を意味するかを示す。
- 最良の結果だけでなく、適用条件・限界・失敗例も適切に示し、主張の信頼性を高める。

### 5. 文字・ラベル・凡例
- フォントは Arial などの可読性の高い書体に統一し、Figure 間で文字サイズ・太さを揃える。
- 最終掲載サイズ（1カラム・2カラム）を想定し、縮小後も文字や線が判読できるようにする。
- 図中の文章は短くし、詳細な説明は Caption に記載する。
- パネルラベル（a, b, c, …）は太字で明確に表示し、位置とサイズを統一する。
- 軸ラベルには変数名・単位を明記し、略語や記号の意味を明確にする。
- 凡例は可能な限り Figure 全体で共有し、各パネルでの重複を避ける。
- 長いタイトルや説明文をグラフ内部に配置せず、視覚的な情報を優先する。

### 6. Caption・独立性
- Figure と Caption だけで主要な内容を理解できるようにする。
- Caption の冒頭で Figure 全体の科学的メッセージを簡潔に説明する。
- 各パネル（a–d など）の内容を順番に説明し、図中の記号・色・略語を定義する。
- 定量評価では、サンプル数・反復回数・誤差棒の定義・統計手法などを必要に応じて明記する。
- 本文では Figure を単に参照するのではなく、各パネルがどの科学的主張を裏付けるのかを説明する。

### 7. Table・出力品質
- Table は正確な数値比較に使用し、Figure は傾向・構造・差異の直感的な理解に使用する。
- Table の列数・行数を必要最小限にし、主要な比較指標を優先する。
- 太字などによる強調は限定的に使用し、最良値や重要な結果を識別しやすくする。
- 不要な縦罫線や過度な色付けを避け、整然としたレイアウトにする。
- Figure は可能な限りベクトル形式（PDF・SVG・EPS など）で作成し、拡大・縮小しても品質が低下しないようにする。
- 最終的には投稿先の公式ガイドラインに従い、解像度・フォント・線幅・ファイル形式を調整する。

### 特に重要な7原則
1. **Storytelling** — Figure 全体で研究の論理的なストーリーを構築する。
2. **Novelty** — 従来研究との本質的な違いを一目で理解できるようにする。
3. **Scientific impact** — 単なる性能比較ではなく、新しい科学的知見や実用上の意義を示す。
4. **Information density** — 情報密度を高めながら、可読性と余白を維持する。
5. **Visual consistency** — 配色・フォント・レイアウト・軸・凡例を統一する。
6. **Quantitative evidence** — 定量比較・不確実性・具体例によって主張を裏付ける。
7. **Self-contained** — Figure と Caption だけで、主要な科学的メッセージが理解できるようにする。

最も重要なのは、Figure を「結果の表示」ではなく「科学的主張を視覚的に論証する手段」として設計すること。

## B. Nature 技術仕様（Nature Research Figure Guide より）

出典: research-figure-guide.nature.com の "Preparing figures – our specifications",
"Building and exporting figure panels", "Image integrity", "Extended data formatting guidelines"。
Nature Communications 等の姉妹誌も概ね同じだが、投稿前に各誌の最新ガイドを確認すること。

| 項目 | 仕様 | nfig / スクリプトでの対応 |
|---|---|---|
| 幅 | 1カラム 89 mm、2カラム 183 mm（中間 120–136 mm） | `nfig.figure("single"/"onehalf"/"double")` |
| 高さ | 最大 170 mm（下に Legend の余地を残す） | `figure()` が警告、QAでERROR |
| 書体 | Arial / Helvetica 等の標準サンセリフ。ギリシャ文字は Symbol 可 | `use_style()` |
| 文字サイズ | 全テキスト 5–7 pt（パネルラベル以外） | 本文7 pt・目盛り/凡例6 pt。上付き/下付きも5 pt以上に保つ |
| パネルラベル | 8 pt、太字、直立、小文字（a, b, c） | `label_panels()` |
| 文字の扱い | 編集可能なまま（アウトライン化しない）。TrueType 2/42 で埋め込み、Type 3 不可 | `pdf.fonttype=42`, `svg.fonttype='none'` |
| 色付き文字 | 避ける。凡例は色付きの記号＋黒文字、図中は黒い引き出し線＋黒文字 | QAが警告。`end_labels()` は黒文字 |
| 配色 | 色覚多様性に配慮（Wong 2011 パレット推奨）。赤/緑の組合せと虹色スケールを避ける。WCAG 2.1 AA、文字のコントラスト比 4.5 以上 | `Palette`（Wong系を低彩度化）、`viridis`/`RdBu_r` |
| グラフ | 軸線と目盛りは必須。軸ラベルは「Quantity (unit)」。背景グリッド・影・パターン・文字の重なりを避ける | `use_style()`、QA |
| アイコン | 装飾的なアイコンは使わず文字で。現実の文脈を補うものだけ可 | 概要図の方針（storyboard.md） |
| 余白・順序 | 余白を最小化、パネルはアルファベット順に配置、各パネルは内容に見合う大きさに | storyboard.md |
| 画像 | RGB。写真は最終サイズで 300 dpi 以上（450 dpi 以上が望ましい）。拡大補間は無意味 | QA / assemble の dpi 報告 |
| スケールバー | 倍率表記ではなくスケールバー。バーとラベルは編集可能なベクターで | `image_panel(scalebar=...)` |
| ファイル形式（本文Figure） | .pdf / .eps / .ai（ベクター、編集可能）が推奨。plain .svg も可。JPEG/PNG/TIFF は不可。50 MB 未満 | `save()` が PDF/SVG/PNG を出力（PNG は確認用） |
| Extended Data | RGB、最大 300 dpi、10 MB 以下、.jpeg（推奨）/.tiff/.eps、1ページに Legend 込みで収める | PDF を 300 dpi で JPEG 化して提出 |
| 画像の誠実性 | 調整は画像全体に一様に。部分的なレタッチ・クローン・消去・生成AI編集は不可。異なる時点/試料の画像の合成は不可（並べる場合は境界を示し Legend に記載）。ゲル/ブロットは未加工の元画像を提出 | `image_panel` はトリミングと縮尺のみ |

一般的な実務値（公式の数値指定はないが広く使われる値）: 線幅 0.25 pt 以上（nfig 既定は軸 0.5 pt・
データ線 0.9–1.25 pt）、目盛り長 2–3 pt。

## C. 最終チェックリスト（Step 6 で1項目ずつ確認）

### ストーリー
- [ ] 主張が1文で言え、それが Caption のタイトル文になっている
- [ ] 3秒見て主張が伝わる。hero パネルが最も大きく目立つ位置（左上/最上段）にある
- [ ] パネルが左上→右下の順に論理展開し、ラベルもその順（a, b, c…）
- [ ] 従来手法との違い（何が新しいか）が視覚的に分かる
- [ ] 数値の改善に具体例が添えられている。限界・失敗例が本文かSIに示されている
- [ ] 主張に寄与しないパネルがない（あればSIへ）

### レイアウト
- [ ] 幅が 89 / 120–136 / 183 mm、高さ ≤ 170 mm
- [ ] 同種グラフのサイズ・軸範囲・目盛り・ラベル位置が揃い、縦横の端が整列している
- [ ] 意味のない余白がなく、かつパネル間・文字と線の間に呼吸できる余白がある
- [ ] 文字・凡例・注釈がデータや他の文字と重ならない。図の外にはみ出さない

### 文字
- [ ] すべて Arial/Helvetica、5–7 pt（上付き・下付きも 5 pt 以上）。パネルラベルは 8 pt 太字小文字
- [ ] 軸ラベルに量と単位「Time (s)」。略語は Caption で定義
- [ ] 図中の文章は短い。グラフ内に長いタイトルがない。色付き文字がない
- [ ] P 値は斜体の *P* と正確な値（例: *P* = 3.2 × 10⁻⁴）

### 色と線
- [ ] 意味を持つ色は3–5色。提案手法＝アクセント色、比較対象＝灰色系が全Figureで共通
- [ ] 色覚シミュレーションとグレースケールでも区別できる（マーカー・線種・濃淡を併用）
- [ ] 赤/緑の組合せ、虹色カラーマップ、グリッド、影、3D、装飾枠がない
- [ ] 線幅 ≥ 0.25 pt。データ線は軸線より太い

### 定量的証拠
- [ ] 平均だけでなくばらつき（SD/CI）や個々のデータ点が見える。n と誤差棒の定義を Caption に記載
- [ ] 棒グラフは 0 始まり。差を誇張する軸の切り詰めがない。桁違いの量は対数軸
- [ ] 統計検定の名前・片側/両側・多重比較補正を Caption に記載（不明なら `[AUTHOR TODO]`）

### ファイル
- [ ] PDF（フォント埋め込み TrueType、Type 3 なし）と SVG。写真は 300 dpi 以上
- [ ] 図スクリプトだけで再生成できる（`paper_figures/src/`）
- [ ] Table は編集可能なテキスト（画像にしない）、縦罫線なし、最良値のみ太字
